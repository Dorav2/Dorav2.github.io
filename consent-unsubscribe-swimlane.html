营销同意与退订 · 系统泳道图（连线版）

五条横向泳道 = 五个系统；连线序号 ①–⑪ 为调用顺序（对应下方清单）。绿色箭头=同意/状态变化路径；灰色箭头=消息与兜底事件路径。

调用顺序（对应连线序号）

  1. 1顾客勾营销同意（注册 / 绑定 / 个人资料页，同一同意位）
  2. 2CRM：目的级同意位＋渠道偏好落库、留痕
  3. 3发送前 CRM 按五条件过滤名单（未同意者剔除）
  4. 4消息渠道：模板硬校验（无退订链接拦截）＋逐人生成 token 直链
  5. 5经 Messaging API 发出 → LINE 送达好友（无状态）→ 顾客收到消息
  6. 6入口A：LINE 内置浏览器打开我们的 H5（token 定位，免登录）
  7. 7消息渠道校验 token → 改 CRM 同意位
  8. 8入口B：个人资料页关开关 → 同一同意位；两入口都「撤回即时生效、可重新订阅」
  9. 9兜底：顾客取关/拉黑 → LINE 推 webhook（仅好友关系，≠营销退订）
  10. 10消息渠道落关注账本 → CRM 更新可触达名单（区分主动退订 vs 拉黑失联）
  11. 11后台只读展示：绑定数 / 可触达数 / 营销同意数分列
读图重点：绿色箭头（同意状态变化）全部在「顾客触点 ↔ CRM ↔ 消息渠道」之间；LINE 泳道被虚线框住——只承担送消息（④⑤）、打开链接的环境（⑥）、推好友事件（⑨），没有任何箭头把「同意位」连向 LINE。
两个易混点：① 取关/拉黑（LINE 好友关系，webhook 单向同步）≠ 营销退订（CRM 同意位，双入口直改）；② 「可发营销」五条件（目的同意∧渠道开关∧已绑定∧已关注∧未拉黑）由 CRM 发送前一并校验，LINE 不校验。
